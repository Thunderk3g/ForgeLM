# ForgeLM

Model customization platform: FastAPI microservices in `src/microservices/`, a React
dashboard in `frontend/`, and a hardware-agnostic core package in `forgelm/`.
Read `docs/ARCHITECTURE.md` first.

## Commands

- Tests (no GPU, network or model downloads): `python -m pytest tests/factory -q`
- Slow tests that download a small model: `python -m pytest tests/factory -q -m slow`
- Hardware report: `python -m forgelm doctor`
- Experiments: `bash experiments/run_all.sh`, then `python experiments/report.py`

## Conventions

- `forgelm/` must import with only numpy installed. Import torch, transformers,
  scikit-learn and the rest inside the function that needs them.
- Every planner rule cites an entry in `forgelm/evidence.py`. An entry may be
  `measured` only if its result file exists in `experiments/results/`; a test
  enforces this. Do not write a measured claim before the experiment has run.
- `experiments/RESULTS.md` is generated by `experiments/report.py`. Edit the
  generator, not the Markdown.
- Run experiments one at a time. Two torch processes on the same cores slow
  each other by an order of magnitude and corrupt latency figures.
- `.gitignore` ignores `test_*.py` everywhere except `tests/factory/`.
- The training service reaches `forgelm` only through
  `src/microservices/training_service/src/utils/factory_bridge.py`, which falls
  back to the old behaviour when the package is missing.

## Known debt

- Many files under `src/microservices/*/src/{common,utils,services}` are
  byte-identical copies of each other. Change all copies or none.
- GPU training paths cannot be run in a CPU-only environment. Say so when
  changing them.
